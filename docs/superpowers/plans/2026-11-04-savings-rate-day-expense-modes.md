# Savings Rate and Day Expense Modes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Сделать «Норму накопления» читаемой при выбросах и добавить на «День за днём» режим «Без разовых» наряду со «Все» и «Повседн.».

**Architecture:** Оба изменения остаются в существующем разделе `stats.js` внутри `index.html`; новых модулей и зависимостей нет. Три режима расходов используют общий фильтр `_dayExps()`, а `_monthForecast()` лишь отдаёт дополнительный накопительный ряд будущих трат без разовых, не меняя формулы. Ограничение шкалы нормы накопления не меняет исходные данные графика.

**Tech Stack:** Ванильный JavaScript, HTML, Chart.js, Puppeteer (`tools/dt-check.mjs`).

**Spec:** `docs/superpowers/specs/2026-11-04-savings-rate-day-expense-modes-design.md`

## Global Constraints

- Не изменять `pace`, `specRemain`, `fc.total`, среднюю норму накопления и финансовые данные.
- Не добавлять зависимости, сборку или отдельные JS-файлы.
- Не переносить локальный UI-режим в `DB` или payload синхронизации.
- Сохранять существующие глобальные функции, компактный стиль и русские подписи.
- Не использовать реальный бэкап в тестовых фикстурах и не коммитить изменения без отдельного запроса пользователя.

## Review Focus

- Разовая трата внутри обязательной категории: `noOneoff` должен исключить её, `all` — включить; проверяется в Task 1, тест фильтров.
- Будущая разовая трата: не должна попасть в нарисованный прогноз `noOneoff`, но должна остаться в полном `fc.total`; проверяется в Task 1, тест прогноза.
- Месяц без учёта трат или дохода: ограничение шкалы не должно превратить `null` в нулевой столбец или подпись выброса; проверяется в Task 2, тест пустых значений.
- Некорректное локально сохранённое значение режима: должен безопасно действовать `all`; проверяется в Task 1, тест миграции.
- Малый мобильный график: подпись выброса не должна перекрывать соседние месяцы, а три кнопки должны оставаться внутри карточки; проверяется в Task 3 визуально и геометрически.

**Interfaces:**
- Produces: `dayExpenseMode: 'all' | 'daily' | 'noOneoff'`.
- Produces: `setDayExpenseMode(mode)` — принимает только три значения, остальные заменяет на `'all'`, сохраняет через `uiSet('dayExpenseMode', mode)` и вызывает `renderStats()`.

- Extends: результат `_monthForecast()` полем `futLineNoOneoff`, аналогичным `futLine`/`futLineReg`.
