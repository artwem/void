# Центрирование рабочих вкладок на десктопе — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Центрировать «День», «Бюджет» и «Доходы» в десктопной рабочей области и расширить их до 1040 px, не меняя мобильную версию.

**Architecture:** Изменяются только десктопные CSS-правила существующих страниц и положение общей плавающей кнопки. Геометрия закрепляется проверками Puppeteer в существующем `tools/dt-check.mjs`.

**Tech Stack:** HTML, CSS, vanilla JavaScript, Puppeteer через существующий harness.

**Spec:** `docs/superpowers/specs/2026-11-04-desktop-input-pages-centering-design.md`

## Global Constraints

- Меняются только «День», «Бюджет» и «Доходы» при viewport от 1000 px.
- Мобильная раскладка, содержимое страниц и их поведение не меняются.
- «Настройки» сохраняют прежнюю ширину 760 px; двухколоночные страницы не затрагиваются.
- Не добавлять зависимости, отдельные JS-файлы или шаг сборки.
- Не выполнять commit или deploy без отдельной просьбы пользователя.

## Review Focus

- Viewport 1000 px: контент должен занять все 936 px после сайдбара 64 px без пустых боковых полей.
- Viewport 1280 px: колонка 1040 px должна иметь поля по 16 px внутри рабочей области после сайдбара 208 px.
- Viewport 1600 px: колонка должна остаться 1040 px и центрироваться именно между сайдбаром и правым краем, а не по центру всего viewport.
- FAB на «Бюджете»: кнопка должна оставаться в 16 px от правого края контента при обеих ширинах сайдбара.
- Viewport 390 px: ширина body и страниц должна остаться мобильной, без горизонтального переполнения.

### Task 1: Центрированная колонка и геометрические проверки

**Files:**
- Modify: `tools/dt-check.mjs:119-165`
- Modify: `css/app.css:555-564`
- Modify: `css/app.css:654-662`

**Interfaces:**
- Consumes: существующие `suite(width, title, fn)`, `check(name, fn)`, `rect(page, selector)` и `near(actual, expected, what, tolerance)`.
- Produces: десктопная геометрия трёх страниц `#page-day`, `#page-budget`, `#page-income`; отдельных программных интерфейсов нет.

- [ ] **Step 1: Обновить и добавить failing-проверки геометрии**

В `tools/dt-check.mjs` заменить проверку «страница начинается сразу после сайдбара» на проверку трёх вкладок при 1280 px: каждая имеет `x=224`, `width=1040`. Добавить сюиты при 1000 и 1600 px:

- при 1000 px каждая из трёх страниц имеет `x=64`, `width=936`;
- при 1600 px каждая имеет `x=384`, `width=1040`;
- на «Бюджете» при 1000, 1280 и 1600 px правая граница `#fab` равна правой границе `#page-budget` минус 16 px;
- при 390 px все три страницы имеют `x=0`, `width=390`, а `document.documentElement.scrollWidth <= innerWidth`.

Перед каждым измерением вызывать `showPage()` для соответствующей вкладки, чтобы не измерять скрытый элемент.

- [ ] **Step 2: Запустить проверки и убедиться в ожидаемом FAIL**

Run: `CHROME_PATH='/Applications/Google Chrome.app/Contents/MacOS/Google Chrome' node tools/dt-check.mjs`

Expected: новые проверки FAIL на прежних `x=208`, `width=760` и прежнем положении FAB; неизменные проверки не должны быть удалены ради зелёного результата.

- [ ] **Step 3: Изменить десктопный CSS**

В `css/app.css` отделить `#page-settings` от трёх рабочих вкладок. Для `#page-day`, `#page-budget`, `#page-income` задать `width:100%`, `max-width:1040px`, `margin-inline:auto`; для `#page-settings` оставить `max-width:760px`.

Для FAB использовать `left:auto` и адаптивный `right`, равный 16 px у правого края центрированной колонки. В блоке от 1000 px учесть сайдбар 64 px, в блоке от 1200 px — 208 px; при недостаточной ширине внешнего поля применять минимум 16 px через CSS `max()`.

Обновить соседние комментарии, чтобы они описывали центрированную колонку 1040 px вместо левой колонки 760 px.

- [ ] **Step 4: Запустить полный набор браузерных проверок**

Run: `CHROME_PATH='/Applications/Google Chrome.app/Contents/MacOS/Google Chrome' node tools/dt-check.mjs`

Expected: PASS всех сюит, включая новые проверки и мобильную базу.

- [ ] **Step 5: Проверить результат визуально**

Снять «День», «Бюджет» и «Доходы» на ширинах 1000, 1280 и 1600 px через существующий `tools/harness.mjs`; сравнить с исходными снимками. Убедиться, что поля симметричны внутри рабочей области, FAB находится у контента, а строки и формы не растянуты на весь экран. Удалить созданные для этой проверки временные снимки, если они больше не нужны.
