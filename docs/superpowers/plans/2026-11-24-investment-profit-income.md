# Investment Profit Income Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** При новом полном выводе с прибылью автоматически предлагать создать доход с тегом «Инвестиции», не записывая убыток или нулевой результат.

**Architecture:** Расширить существующую модалку `modal-inv-contrib` только для режима «Вывести всё». В `saveInvContribution()` вычислить результат по черновику счёта после операции; если счёт стал нулевым и результат положительный, создать обычную запись `DB.incomes` и при необходимости добавить тег в синхронизируемые справочники. Банковские переводы, снимки и расчёт стоимости не менять.

**Tech Stack:** Ванильный JavaScript и HTML в `index.html`, Node VM/Puppeteer-проверки в `tools/dt-check.mjs`.

**Spec:** `docs/superpowers/specs/2026-11-24-investment-profit-income-design.md`

## Global Constraints

- Доход создаётся только для новой операции полного вывода, после которой текущий остаток равен нулю, а результат строго больше нуля.
- Дата дохода равна дате вывода; копейки сохраняются через `parseMoney()`.
- Источник: `Прибыль по инвестициям <название счёта>`; тег по умолчанию: `Инвестиции`.
- Новые списки/записи получают корректные `updatedAt`/`touchList()`; старые архивные счета не мигрируются.
- Доход самостоятелен: последующие правки операций и снимков его не меняют.
- Не добавлять зависимости, отдельные JS-файлы или сборку; не выполнять git-операции без отдельного запроса пользователя.

## Review Focus

- Частичный вывод с положительным результатом не должен создавать доход — проверка в шаге 1.
- Убыток и нулевой результат не должны создавать отрицательный или нулевой доход — проверка в шаге 1.
- Снятая галочка должна предотвращать и создание дохода, и изменение справочника тегов — проверка в шаге 1.
- Полный вывод задним числом при более позднем снимке не должен считаться текущим закрытием — проверка в шаге 1.
- Существующий тег «Инвестиции» не должен дублироваться, а выбранный пользователем другой тег должен сохраняться — проверка в шаге 1.
