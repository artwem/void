# Десктопная раскладка V.O.I.D.

Дата: 2026-08-20
Статус: согласовано, готово к плану реализации

## 1. Задача

Приложение живёт в колонке 430 px и на мониторе выглядит узкой лентой посреди
пустоты. Нужна десктопная версия: весь функционал сохраняется, раскладка
использует ширину, визуальный язык остаётся общим с мобильной версией.

Основной сценарий работы с компьютера — **анализ и разбор**: графики,
«День за днём», годовой отчёт, прогноз, сверка активов. Не ввод трат и не
массовая правка данных. Раскладка оптимизируется под это.

Ключевое ограничение: `index.html` — единственный источник JS, сборки нет,
CSS живёт в `css/app.css`. Десктоп обязан быть **слоем поверх** существующего,
а не вторым приложением: иначе через два релиза версии разъедутся.

## 2. Границы

Входит:

- Оболочка: сайдбар, контекстная колонка месяца, рабочая область, инспектор.
- Три брейкпоинта, ниже 1000 px мобильная вёрстка не меняется.
- Вендоренная гарнитура (Golos Text + JetBrains Mono), в том числе на мобиле.
- Десктопные амплуа для всех 28 оверлеев.
- Раскладка всех вкладок в широком режиме.
- Редактор лимитов прямо на странице «Бюджет» (не в модалке).
- Puppeteer-харнесс для снятия скриншотов всех состояний.

Не входит:

- Страница «Разбор» (тепловая карта год × категория) — обсуждалась как
  вариант 3, отложена до готовности оболочки.
- Горячие клавиши и навигация с клавиатуры сверх `Escape`.
- Переписывание содержимого модалок. Меняется только их позиционирование.
- Любые изменения расчётов: `_monthForecast`, `_budgetFree`, `_buildAssetSeries`
  и прочая математика не трогается.

## 3. Оболочка

### Сетка и брейкпоинты

Точка входа — `@media (min-width:1000px)` в `css/app.css`. Ниже порога не
добавляется ни одного правила.

| Ширина | Сайдбар | Контекст | Рабочая область | Инспектор |
|---|---|---|---|---|
| < 1000 | нижний таб-бар | скрыт | вся ширина | нижняя шторка |
| 1000–1199 | 64 px, только иконки | 280 px | `1fr` | наезжает справа |
| 1200–1439 | 208 px, иконки + подписи | 296 px | `1fr` | наезжает справа |
| ≥ 1440 | 208 px | 296 px | `1fr` | 380 px, четвёртая колонка |

Сайдбар в диапазоне 1000–1199 px схлопывается в иконочный рельс 64 px: подписи
убираются, названия вкладок остаются в `title` и `aria-label`.

`body` становится гридом (ниже — вариант для ≥1200 px; при 1000–1199 треки
`64px 280px`):

```css
body{
  max-width:none; padding-bottom:0;
  display:grid; min-height:100vh;
  grid-template-columns:208px 296px minmax(0,1fr);
  grid-template-areas:"nav ctx main";
}
body.insp-open{ grid-template-columns:208px 296px minmax(0,1fr) 380px; }
```

Четвёртый трек добавляется только при ≥1440 px; ниже инспектор остаётся
`position:fixed` и накрывает рабочую область.

### Изменения в DOM

Минимальны. Существующие `.page` не переписываются — получают `grid-area:main`.

- `nav.nav` из `position:fixed` внизу → `position:sticky; top:0; height:100vh;
  flex-direction:column`. Разметка, иконки и `showPage()` не меняются.
- Новый узел `<aside id="dt-ctx">`, на мобиле `display:none`. Наполняется новой
  `renderDeskCtx()`.
- Отдельного контейнера под инспектор **не создаётся**: при ≥1440 px роль
  четвёртой колонки играет сам `.overlay` (см. раздел 6), он уже прямой потомок
  `body`, то есть валидный грид-элемент.
- Анимации `slide-l` / `slide-r` при ≥1000 px заменяются на fade: горизонтальный
  въезд страницы при боковом сайдбаре читается как сбой.
- FAB (`#fab`) прячется. Вместо него кнопка «+ Расход» в шапке контекста.

### Контекстная колонка

Липкая, не скроллится вместе с рабочей областью. Содержимое:

1. Навигация по месяцу `‹ Июль 2026 ›`.
2. Кнопка «+ Расход».
3. Потрачено / Лимит / Остаток / Прогноз.
4. Прогресс-бар месяца.
5. Топ-6 категорий по тратам с лимитом и процентом.

`renderDeskCtx()` не считает ничего собственного — берёт готовые `getLimits`,
`getCatSpent`, `getMonthExpenses`, `_monthForecast`, `_budgetFree`. Вызывается
там же, где `renderBudget()`.

## 4. Состояние месяца

Сейчас месяц раздроблен: `currentMonth` (бюджет), `currentDay` (день),
`currentIncomeMonth` (доходы), плюс собственные `<select>` месяца внутри
графиков аналитики.

Решение:

- При ≥1000 px **контекстная колонка — единственный навигатор по месяцу**. Она
  управляет `currentMonth`, `currentIncomeMonth` и `currentDay`. День зажимается
  в границы месяца: при переключении встаёт на 1-е число, либо на сегодня, если
  месяц текущий.
- Помесячные шапки внутри вкладок «Бюджет» и «Доходы» при ≥1000 px скрываются:
  два конкурирующих контрола на одном экране недопустимы.
- Навигация по дню на вкладке «День» **остаётся на странице**. День — другая
  гранулярность, контекст про месяц.
- Селекты месяца внутри графиков аналитики (`pie-month-sel`,
  `day-compare-month-sel`) **остаются независимыми**. Это инструменты сравнения,
  а не навигация; привязка к глобальному месяцу сломала бы сопоставление
  месяцев в «День за днём».

## 5. Типографика

Вариант **Б**: Golos Text для текста, JetBrains Mono для цифр.

| Файл | Что | Вес |
|---|---|---|
| `vendor/golos-text.woff2` | Golos Text, переменный 400–700, латиница + кириллица + ₽ + типографская пунктуация | 46,6 КБ |
| `vendor/jetbrains-digits.woff2` | JetBrains Mono, переменный 400–700, только цифры и денежные знаки | 3,0 КБ |

Проверенные факты (замеры, не оценки):

- `tnum` у Golos Text есть, но по умолчанию активен `pnum` — табличные цифры
  надо включать явно через `font-variant-numeric: tabular-nums`.
- Знак рубля U+20BD лежит в latin-ext, поэтому сабсет обязан его включать.
- Символы `✓ ✕ ✎ ↻ ↳ ⌀ ∅ Δ ▓ ⬇ ⚡` в Golos Text **отсутствуют** — их будет
  рисовать системный шрифт. Фолбэк-стек обязателен и осознан, не «на всякий
  случай».
- Ширина «128 728₽» при 27 px: системный 113, Golos 125, JetBrains 130,
  Unbounded 156 px. Числу в строке контекстной колонки доступно 192 px
  (264 минус подпись и зазор), так что запас есть у всех.

Фолбэк-стеки задаются явно, с расчётом на отсутствующие символы:

```css
--font-text:'Golos Text',-apple-system,BlinkMacSystemFont,'Segoe UI',Roboto,sans-serif;
--font-num:'JetBrains Mono',ui-monospace,'Cascadia Mono',Consolas,monospace;
```

Сабсеты собираются один раз локально через `pyftsubset` и коммитятся как
готовые файлы; в рантайме и в CI ничего не собирается.

Шрифт применяется **и к мобильной версии**. Разная типографика на телефоне и
на компьютере противоречит требованию визуального единства. Откат — одна
CSS-переменная со стеком шрифтов.

Оба файла добавляются в `PRECACHE` в `sw.js` (сейчас там 630 КБ вендора,
+49,6 КБ — шум).

## 6. Инспектор

### Что обнаружено

Все 28 оверлеев устроены единообразно: `<div class="overlay"><div class="sheet">`,
все — прямые потомки `body`, у каждого `.sheet` уже есть кнопка `.close-btn`.
`openModal(id)` — одна строка, добавляющая класс `.open`.

Следствие: **содержимое модалок переписывать не нужно**. Меняется только
позиционирование `.overlay` и `.sheet` на десктопе. Вся логика, валидация,
обработчики и вызовы `render*` остаются нетронутыми.

### Три амплуа

Каждому оверлею в разметке проставляется атрибут `data-dt`; CSS при ≥1000 px
разводит их по типам.

| `data-dt` | Оверлеи | Вид на ПК |
|---|---|---|
| `insp` | `modal-expense`, `modal-income`, `modal-cat-expenses`, `modal-template`, `modal-goal`, `modal-goal-topup`, `modal-deposit`, `modal-dep-contrib`, `modal-close-deposit`, `modal-investment`, `modal-inv-snap`, `modal-inv-contrib`, `modal-grace`, `modal-split`, `modal-split-view` | правая панель 380 px во всю высоту, свой скролл |
| `dialog` | `modal-limits`, `modal-cats`, `modal-banks`, `modal-templates`, `modal-income-tags`, `modal-asset-edit`, `modal-data-audit`, `modal-script`, `modal-sync`, `modal-sync-choice`, `modal-about` | окно по центру, ширина по содержимому до 560 px |
| `confirm` | `modal-confirm-clear`, `modal-delete-income-tag` | компактное окно 380 px по центру |

`.sheet::before` (полоска-хваталка нижней шторки) при ≥1000 px скрывается.

### Механика

- **1000–1439 px**: `.overlay[data-dt="insp"]` остаётся `position:fixed`,
  прижат вправо; затемнение накрывает только рабочую область, сайдбар и
  контекст остаются рабочими.
- **≥1440 px**: `position:static; grid-area:insp` — тот же элемент становится
  четвёртой колонкой грида и ничего не перекрывает.
- `openModal` / `closeModal` получают по три строки: переключение
  `body.insp-open` для оверлеев с `data-dt="insp"`.
- `Escape` закрывает верхний открытый оверлей. Сейчас закрытие только тапом по
  подложке, а на десктопе подложки под курсором может не быть. Мобильной версии
  не вредит, на iPad с клавиатурой помогает.

## 7. Раскладка по вкладкам

Сквозное правило: **строки списков не растягиваются на всю ширину**. Там, где
контент линейный, колонка ограничена ~620 px; остальное уходит под вторую
колонку или остаётся полем.

### Аналитика

Пять карточек-графиков в сетку: две колонки при 1280, три при ≥1600 с закрытым
инспектором.

Высоты холстов зашиты инлайном в разметке (`height:190px`, `200px`, `180px`),
а инлайн бьёт CSS. На широкой карточке 190 px выглядит приплюснуто, нужно
240–260. Высоты выносятся в классы `.chart-h-sm` / `.chart-h-md` — примерно
десять мест. Вариант с `!important` отвергнут: он оставит проблему следующему.

### Накопления

Две колонки. Слева — «Текущие счета», «Кредиты», «Цели накоплений», кнопки
вкладов/инвестиций/прогноза. Справа — три графика и таблица истории. Сейчас,
чтобы дойти до счетов, надо проскроллить три графика; порядок переворачивается:
слева то, что правят, справа то, на что смотрят.

### Бюджет

Граница с контекстной колонкой: **в контексте сводка и топ-6 категорий, на
странице все категории целиком** по цветовым группам в 2–3 колонки.

Плюс редактор лимитов прямо на странице (входит в объём): таблица
«категория × лимит × ⌀ подсказка» редактируется на месте, без модалки. При
≥1000 px кнопка «Лимиты ✎» не открывает `openLimitEditor()`, а скроллит к
таблице. Сам `modal-limits` сохраняется с `data-dt="dialog"` — он остаётся
рабочим для мобильной версии и как запасной путь, но на десктопе недостижим.

### День

Слева список трат за день, справа липкая панель: быстрый ввод, чипы шаблонов,
поиск, фильтр категорий. Навигация по дню остаётся на странице.

### Доходы

Сводка «Доход / Расходы / Баланс» на всю ширину, ниже две колонки: слева список
источников, справа фильтр по тегам и кнопка добавления.

### Остальные

- **Прогноз накоплений** — форма слева, график и результат справа.
- **Вклады, Инвестиции** — карточки в две колонки.
- **Годовой отчёт** — помесячная таблица получает воздух, блоки «по категориям»
  и «по тегам» встают рядом.
- **Настройки** — секции в две колонки, ширина строки ограничена.

## 8. Проверка

Тест-раннера в проекте нет, поэтому проверка — скриншотная и ручная.

Puppeteer-харнесс (`puppeteer-core` + системный Chrome, расширение Chrome не
используется — оно не даёт детерминированного размера окна):

1. Поднять `python3 -m http.server 8080`.
2. Пройти по всем вкладкам на ширинах 390, 1000, 1280, 1440, 1600.
3. Открыть каждый из 28 оверлеев на ширинах 390, 1280, 1600.
4. Сложить скриншоты в папку с осмысленными именами, просмотреть глазами.

Скрипт остаётся в репозитории как регрессионный инструмент.

Обязательно проверить руками:

- iPhone PWA после деплоя — вёрстка ниже 1000 px не должна измениться нигде,
  кроме шрифта.
- Офлайн-режим: оба woff2 попали в precache, белого экрана нет.
- Все 10 тем: контекстная колонка и инспектор используют только существующие
  CSS-переменные.
- Приватный режим (`fmtH` / `.prv`) в контекстной колонке и инспекторе.

## 9. Этапность

Порядок выбран так, чтобы после каждого этапа приложение оставалось рабочим и
деплоилось.

1. **Типографика.** Сабсеты, `@font-face`, фолбэк-стек, `tabular-nums` на
   деньгах, precache. Затрагивает и мобилу, поэтому идёт первой и отдельно —
   так регрессию видно изолированно.
2. **Оболочка.** Грид, сайдбар, брейкпоинты, скрытие FAB, fade вместо slide.
   Контекстная колонка ещё пустая.
3. **Контекст месяца.** `renderDeskCtx()`, унификация состояния месяца,
   скрытие помесячных шапок.
4. **Инспектор.** Атрибуты `data-dt`, три амплуа, `body.insp-open`, `Escape`.
5. **Раскладка вкладок.** Включая вынос высот графиков в классы.
6. **Редактор лимитов на странице бюджета.**

Шесть этапов для одного плана реализации многовато. Если при написании плана
объём окажется неподъёмным, естественный шов проходит после этапа 4: 1–4 —
фундамент (типографика, оболочка, контекст, инспектор), 5–6 — раскладка вкладок
и редактор лимитов. Оба куска самодостаточны и деплоятся отдельно.

## 10. Риски

- **Инлайн-стили в разметке.** `padding:0 16px` и фиксированные высоты
  раскиданы по всему `index.html` и бьют десктопный CSS. Лечится точечным
  выносом в классы по мере надобности, но это диффы в файле на 8763 строки.
- **28 модалок × 3 амплуа.** Риск не в коде, а в объёме визуальной проверки.
  Закрывается скриншотным харнессом.
- **Унификация месяца** — единственное по-настоящему инвазивное место. Задевает
  `changeMonth`, `changeDay`, `changeIncomeMonth`, `onBudgetMonthChange`,
  `onIncomeMonthChange`. Ошибка здесь ломает мобильную версию тоже.
- **Шрифт на мобиле** — заметное изменение того, чем пользуются ежедневно.
  Откат однострочный.

## 11. Чеклист деплоя

Стандартный для проекта, без отступлений:

1. Поднять видимую версию в `index.html` (блок About).
2. Поднять `const V` в `sw.js`.
3. Поднять `?v=` у `css/app.css` в `<link>`.
4. Добавить оба woff2 в `PRECACHE`.
5. Push в `main`, проверить сборку Pages через `gh api`.
