# V.O.I.D. как личный Telegram Mini App

## Замысел и результат

Запустить существующий V.O.I.D. целиком внутри Telegram для личного использования. Пользователь открывает Main Mini App через бота, работает со всеми текущими вкладками и функциями, а при настройке той же Apps Script синхронизации обменивается данными с PWA.

Первая версия не сокращает функциональность и не переносит приложение в HTML-сообщение. Mini App — обычный HTTPS WebView, поэтому текущие разметка, финансовые расчёты и размеры ресурсов подходят без переписывания.

## Цели

- Один `index.html` остаётся источником разметки и прикладного JS для браузера, PWA и Telegram.
- В Telegram приложение раскрывается на доступную высоту, сообщает `ready()`, учитывает системные отступы и не перекрывается UI Telegram.
- При теме `auto` приложение следует светлой/тёмной теме Telegram; явно выбранная тема V.O.I.D. сохраняется.
- Telegram SDK доступен офлайн так же, как остальные runtime-ресурсы; новых CDN-зависимостей нет.
- Существующие `DB`, `localStorage`, резервные копии и цикл Drive pull → merge → push продолжают работать без изменения формата.
- Обычный браузер и PWA не получают видимых или поведенческих изменений.

## Не входит в первую версию

- HTML-виджеты внутри сообщений, бот-команды, уведомления через бота и Bot API backend.
- Публичная регистрация, серверная проверка `initData`, централизованное хранение нескольких пользователей.
- Перенос данных в `DeviceStorage`/`SecureStorage`, автоматическая миграция localStorage из PWA.
- Отдельный урезанный интерфейс, Telegram MainButton/BackButton, haptics и новые startapp-команды.
- Изменение финансовой логики, схемы данных, Apps Script и протокола синхронизации.
- Автоматическая публикация в `main` и действия в BotFather без отдельного разрешения пользователя.

Не должно получиться так, чтобы Telegram стал обязательным для PWA, чтобы пустое хранилище Telegram автоматически затёрло Drive или чтобы токен бота/синхронизации попал в клиентский payload, логи или документацию.

## Подходы

1. **Полный Mini App — выбрано.** Использовать текущий сайт и добавить небольшой адаптер Telegram. Сохраняются все функции и существующая модель данных; объём изменений минимален.
2. **Урезанный Mini App.** Отдельный режим с быстрым расходом и сводкой. Быстрее для пользователя, но требует продуктовых решений и дополнительных веток UI; отложено.
3. **HTML-виджет в сообщении.** Не подходит для переноса приложения: лимиты 32 КБ/4 КБ zlib, отсутствие сети, внешних ресурсов, полей ввода и прокрутки. Может позже стать отдельной карточкой сводки, но потребует backend.

## Реализация

### Подключение и жизненный цикл

- Сохранить официальный `telegram-web-app.js` как `vendor/telegram-web-app.js` и подключить локально в `<head>` перед остальными скриптами, как требует Telegram. Файл добавить в `PRECACHE`; npm-зависимость и сборщик не нужны.
- Добавить компактную секцию `telegram.js` в основной inline script `index.html`. Все обращения к `window.Telegram.WebApp` идут через защищённые хелперы; вне Telegram адаптер не делает вызовов и не мешает запуску.
- Реальная среда определяется по наличию WebApp и платформе, отличной от `unknown`. Пустой объект SDK в обычном браузере не считается Telegram.
- При запуске вызвать `expand()` и подписаться на изменения темы и safe area. После `loadDB()`, первоначального `renderDay()` и применения темы вызвать `ready()`.
- Повторная инициализация не должна дублировать подписки. Методы, зависящие от версии Bot API, вызываются только при поддержке и не могут прервать основной `init()`.
- Не запрашивать полноэкранный режим: `expand()` раскрывает Mini App на доступную высоту, а `requestFullscreen()` меняет модель отображения и не нужен для финансового интерфейса.

### Тема и цвета оболочки

- В `applyTheme()` режим `auto` в Telegram выбирает класс `light` или `dark` по `WebApp.colorScheme`; остальные темы и существующая CSS-палитра не заменяются палитрой Telegram.
- На событие `themeChanged` повторно применить тему и перерисовать текущую страницу только при `auto`, чтобы графики получили актуальные CSS-цвета. Явную тему пользователя событие не переопределяет; цвет оболочки Telegram всё равно синхронизируется.
- После вычисления фактического `body.backgroundColor` передавать шестизначный цвет в `setHeaderColor()` и `setBackgroundColor()`; `setBottomBarColor()` вызывать при поддержке Bot API 7.10+. Текущий `meta[name="theme-color"]` сохраняется.
- Ранняя инициализация темы в `<head>` учитывает Telegram, чтобы уменьшить вспышку неправильной темы до загрузки основной базы.

### Safe area и раскладка

- Ввести CSS-переменные для Telegram content safe area с нулевыми значениями по умолчанию и обновлять их из `contentSafeAreaInset` при старте и событиях `safeAreaChanged`/`contentSafeAreaChanged`.
- Нижний отступ вычислять как максимум существующего `env(safe-area-inset-bottom)` и Telegram content inset. Использовать общую переменную в body, нижней навигации, FAB, sheets и `.page-end`, не дублируя отступы.
- Верхний Telegram inset учитывать в начальном отступе body и `top` липких шапок; модалки не должны ставить интерактивные элементы под UI Telegram. Вне Telegram переменные равны нулю, поэтому текущая геометрия сохраняется.
- Не менять существующие 430 px, десктопные breakpoints, pinch-zoom и `prefers-reduced-motion`.

### Данные и синхронизация

- Оставить ключ `budgetDB_v2` и все функции хранения как есть. Telegram WebView имеет отдельное хранилище: первый запуск начинается с пустой локальной базы, это ожидаемо и явно описывается пользователю.
- Не копировать автоматически данные из PWA и не считать Telegram ID заменой существующей авторизации. Для личного сценария пользователь один раз вводит тот же Apps Script URL и токен в настройках Telegram.
- Синхронизация остаётся только через `syncCycle()` с порядком pull → merge → push. Добавление Telegram не создаёт нового прямого push и не меняет `buildPayload()`.
- Существующие query deep links `?add=` и `?tab=` не ломать. Специальный разбор `startapp` в первую версию не добавлять: Main Mini App открывается на стартовой вкладке «День».

### Документация и выпуск

- В README добавить личную настройку: создать бота через `@BotFather`, включить Main Mini App с `https://artwem.github.io/void/`, после публикации открыть его и при необходимости повторно настроить Drive sync. Токен бота для запуска Mini App в коде не нужен и хранить его в репозитории не требуется.
- Обновить `AGENTS.md`: Telegram SDK входит в локальные vendor-ресурсы, адаптер находится в секции `telegram.js` внутри `index.html`.
- Поднять видимую версию до `v1.89.0`, обновить `const V` в `sw.js` и query `?v=` у `css/app.css`. Версия Apps Script остаётся `10.5`.

## Проверка

- Добавить в существующий `tools/dt-check.mjs` Telegram-сюиту с mock `WebApp`, не создавая второй harness или демо-генератор. Проверить: определение Telegram/браузера, `expand()` и `ready()`, отсутствие дублей подписок, auto/explicit темы, передачу цветов, safe-area переменные и устойчивость к старым методам SDK.
- Существующий тест deep links должен остаться зелёным. Базовая мобильная и десктопная геометрия вне Telegram не должна измениться.
- Прогнать синтаксическую проверку всех inline scripts и полный `node tools/dt-check.mjs`. После CSS-изменений снять и просмотреть стандартные screenshots через `node tools/shots.mjs`; сгенерированные shots не коммитить.
- Ручная приёмка после публикации на реальных iOS и Android: запуск через бота, все основные вкладки, добавление и редактирование расхода, модалки и клавиатура, смена темы Telegram, отступы, повторный запуск и офлайн. Затем настроить тот же Apps Script в Telegram и убедиться, что pull → merge → push переносит тестовую трату между Telegram и PWA в обе стороны без потери существующих данных.
- Puppeteer не доказывает поведение настоящего Telegram WebView; до ручной проверки это явно считается непроверенной частью.

## Решения, оставленные разработчику

- Точные имена приватных хелперов и CSS-переменных — в существующем компактном стиле проекта.
- Способ подстановки mock WebApp в существующем Puppeteer-харнессе — без production-зависимости от тестового кода.
- Мелкие защитные проверки поддержки SDK — по фактическому API официального vendor-файла, без нового слоя абстракции.
