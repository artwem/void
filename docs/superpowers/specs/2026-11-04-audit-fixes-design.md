# Исправления аудита 2026-11-04

## Цель и объём

Исправить четыре подтверждённые ошибки без изменения пользовательских сценариев: выполнение JS через ID из восстановленных/синхронизированных данных, неполное авторитетное восстановление копии, удаление чужих Cache Storage при активации SW и невалидные пути скриншотов на macOS/Linux.

Доступность, фоновые push-уведомления и новые функции в этот проход не входят.

## Подходы

- Выбрано: безопасное кодирование динамических JS-аргументов в существующих inline-обработчиках. Минимальный diff, соответствует текущему стилю `index.html`.
- Отклонено для этого прохода: массовый перевод записей на `dataset`/`addEventListener`; архитектурно возможен, но требует широкого UI-рефакторинга.

## Изменения

- Добавить хелпер `jsArg(value)`: `JSON.stringify(String(value))` с последующим `esc()`. Применить ко всем найденным динамическим строковым аргументам ID/дат в inline-обработчиках записей и Drive-копий. Числовые индексы и фиксированные цвета палитры не менять.
- Восстановление: заменять полный набор синхронизируемых данных снимком, включая отсутствующие коллекции как пустые, сохраняя только device-local URL/токен, уведомления, тему и приватность. При авторитетном восстановлении штамповать записи и все LWW-настройки, сбрасывать baselines `limits` и `specPlan`.
- SW: при активации удалять только старые кеши с префиксом `app-`, не трогать остальные кеши origin.
- Скриншоты: заменить ручную обработку `.pathname.slice(1)` на `fileURLToPath()` для обоих вызовов `page.screenshot()`.

## Проверка

Сначала добавить регрессионные проверки, которые падают на текущем коде: вредоносный ID не выполняется и запись открывается; старая неполная копия не оставляет текущие коллекции; последующий pull не перезаписывает авторитетно восстановленные `specPlan`/`catOblig`; чужой кеш переживает активацию; путь скриншота остаётся абсолютным на POSIX.

После исправлений запустить синтаксическую проверку, полный `dt-check`, штатный `shots.mjs` и реальное воспроизведение исходных сценариев. Деплойные версии и кеши вручную не бампать: пользователь запрашивал исправления, не публикацию.
