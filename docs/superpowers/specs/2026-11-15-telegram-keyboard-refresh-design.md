# Обновление клавиатуры Telegram только при изменениях

## Замысел

Пользователь не должен получать «Выберите шаблон» после каждого расхода. Основной ответ на нажатие шаблона — только подтверждение добавления и inline-кнопка «Отменить». Отдельное сообщение с клавиатурой нужно только когда состав шаблонов действительно изменился.

## Цели

- Не отправлять лишнее сообщение при повторных расходах с неизменным набором шаблонов.
- Обновлять постоянную клавиатуру при создании, удалении или изменении шаблона, суммы, категории, комментария или разовости.
- Сохранить доставку недоставленных сообщений при повторной обработке того же update и идемпотентность записи Drive.
- Не менять финансовую логику, существующие данные, undo и `getUpdates`.

## Подходы

1. **Подпись клавиатуры — выбрано.** Хранить в Script Properties подпись активных шаблонов в их порядке. Отправлять клавиатуру только если подпись изменилась. Сохранять подпись после успешной отправки, поэтому сбой Telegram приводит к повторной отправке при следующем update, а не к потере обновления.
2. **Совсем без сообщения клавиатуры — отклонено.** Проще, но клавиатура обновлялась бы только при следующем `/start` или неизвестном тексте, а пользователь выбрал сохранение обновлений при изменении состава.
3. **Два сообщения всегда — отклонено.** Это текущее поведение и причина жалобы.

## Реализация

- Добавить подпись активных шаблонов, которая учитывает все поля, влияющие на кнопку и создаваемый расход; удалённые шаблоны исключаются.
- `/start`, навигация и другие обычные ответы с клавиатурой сохраняют подпись после успешной отправки.
- `_telegramAddTemplate()` сравнивает текущую подпись с сохранённой и отправляет сообщение с новой клавиатурой только при различии.
- Подтверждение расхода с inline-кнопкой «Отменить» отправляется независимо от обновления клавиатуры.
- Первая отправка после внедрения подписи может один раз обновить клавиатуру — это ожидаемо.
- Версия клиента повышается до `v1.91.1`, Apps Script — до `11.2`; версия service worker обновляется для сброса кеша.

## Проверка

- Повторный расход с той же подписью отправляет только подтверждение.
- Изменение суммы, категории, комментария, разовости, состава или порядка шаблонов отправляет обновлённую клавиатуру один раз.
- Сбой отправки клавиатуры не фиксирует подпись и не мешает повторной доставке; расход не дублируется.
- `/start` и навигация сохраняют подпись; удалённые шаблоны не влияют на неё.
- Все существующие server/browser проверки остаются зелёными; реальная проверка в Telegram подтверждает отсутствие повторного «Выберите шаблон».
