## 2. Проекция трат до конца месяца — «День за днём» (v1.36.0)

График «День за днём» (stats.js-секция, `charts.dayCompare`) — кумулятивный line-chart: прошлый месяц, среднее за N мес, текущий месяц.

- Новый dataset «Прогноз»: пунктирная линия от сегодняшней точки до конца месяца.
  - `прогноз(d) = selTotal + темп × (d − сегодня)`, где `темп = selTotal / прошедших дней`.
  - Данные: `null` до индекса `сегодня−1`, далее значения (линия стартует из фактической точки).
  - Стиль: цвет как у текущего месяца (`_chartColors().blue`), `borderWidth: 1.5`, `borderDash`, без заливки, `pointRadius: 0`.
- Показывается только когда выбран текущий месяц **и** режим «весь месяц» (`showFull`). В режиме «до сегодня» и для прошлых месяцев — нет.
- Summary (под графиком): строка «Прогноз на конец месяца: X₽» + сравнение с бюджетом = сумма лимитов месяца (`getLimits(y, m)`): перерасход красным (`#d85a30`), в рамках — зелёным (`#1d9e75`). Если лимиты не заданы (сумма 0) — только прогноз без сравнения.
- Учитывает переключатель «Особые» так же, как остальные линии графика (общий `_dayExps`).
- Первые дни месяца темп шумный — принято, подпись честная («при текущем темпе» в тултипе/summary не требуется, достаточно слова «Прогноз»).

## 3. Кредиты: грейс-трекер + сплиты (v1.37.0)

### Модель данных

Один массив `DB.credits`, два вида записей:

```javascript
// грейс кредитки
{id, kind: 'grace', bank,            // bank — имя из DB.creditBanks
 payoffAmount,                        // сумма к погашению до конца грейса
 graceEnd,                            // 'YYYY-MM-DD'
 updatedAt, _deleted?}

// сплит (BNPL: 4–6 платежей)
{id, kind: 'split', name,             // произвольное имя («Яндекс Сплит — куртка»)
 payments: [{date, amount, paid}],    // явный график; total = сумма payments
 updatedAt, _deleted?}
```

Полный sync-паттерн как у `deposits`: `updatedAt` на каждой мутации (включая тумблер `paid` у платежа сплита — штамп на всю запись), soft-delete, добавить `credits` в `buildPayload`, `mergePullData` (LWW по id), purge тумбстоунов в `loadDB`, дефолт `[]` при загрузке/restore/тест-данных.

Проценты после грейса не моделируем. Итог «Всего активов» и серии графика активов не трогаем — блок чисто информационный (грейс-долг уже минусуется через записи кредитных банков).

### UI (страница Активы)

- **Грейс:** бейдж на строке кредитного банка: «до 15 авг · 43 500₽». Цвет: серый >7 дн, янтарный ≤7, красный ≤3 или просрочен. Тап по бейджу → модалка: банк (select из `creditBanks`), сумма, дата конца грейса, кнопки «Погашено» (soft-delete) и удалить. Добавление: кнопка в блоке кредитных карт (для банков без активного грейса).
- **Сплиты:** блок «Сплиты» рядом с кредитной секцией. Строка: имя, «осталось 3/6 · 7 500₽ · след. 12 авг»; красный акцент если ближайший неоплаченный просрочен. Тап → модалка со списком платежей: галка «оплачен» на каждой строке, «Закрыт» (soft-delete), удалить.
- **Модалка нового сплита:** имя, общая сумма, число частей (4/6/или ввод), чипы интервала «неделя / 2 недели / месяц» (default 2 нед), тумблер «первая оплата сразу / через период» → генерируется график → список строк, каждая редактируется (дата и сумма) до сохранения. `total` после правок = сумма строк (показывать live).
- Все суммы через `fmtH()`, строки через `esc()`.

### Уведомления

`checkCreditNotifications()` (gated `DB.notifsEnabled` + permission, вызов из тех же точек, что и у вкладов):
- грейс: конец через ≤3 дня или просрочен;
- сплит: ближайший неоплаченный платёж завтра или просрочен;
- анти-спам: per-запись штамп раз в 3 дня (паттерн `checkDepositNotifications`).
