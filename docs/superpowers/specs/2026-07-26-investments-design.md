# Раздел «Инвестиции» — дизайн

Дата: 2026-07-26. Статус: одобрено.

## Цель

Учёт брокерских счетов / ИИС в V.O.I.D. максимально просто: видеть общий капитал и его рост, без акций, тикеров, котировок и прочей банковской атрибутики. Модель: ручные снимки стоимости + журнал пополнений/выводов. Приложение считает прибыль и доходность.

## Модель данных

Новый массив `DB.investments`:

```js
{
  id,                // uid()
  name,              // «Т-Инвестиции», «ИИС ВТБ»
  snapshots: {       // стоимость счёта на дату, ручной ввод
    '2026-07-26': 1250000,
    ...
  },
  contributions: [   // пополнения и выводы
    {id, date, amount, updatedAt}   // amount < 0 = вывод
  ],
  updatedAt,         // LWW-sync на уровне всей записи
  _deleted           // soft-delete (tombstone), как у deposits
}
```

### Стоимость на дату — `invValueAt(inv, dateStr)`

1. Берём последний снимок с датой ≤ `dateStr` (carry-forward).
2. Прибавляем все пополнения/выводы с датой строго после даты этого снимка и ≤ `dateStr`.
3. До первого снимка счёт не существует (значение 0, в серии не участвует).

Следствие: пополнение видно в стоимости сразу, без нового снимка; следующий снимок «перебазирует» стоимость фактом.

### Прибыль

- Вложено = Σ пополнений − Σ выводов (все contributions с датой ≤ сегодня).
- Прибыль ₽ = текущая стоимость − вложено.
- Прибыль % = прибыль / вложено (если вложено > 0). Без XIRR/годовой доходности — осознанно.

### Создание счёта

Модалка: имя, дата (по умолчанию сегодня, можно задним числом), «Вложено всего» (записывается стартовым contribution на эту дату), «Стоимость сейчас» (первый снимок на ту же дату). Селект банка в модалке создания не показываем — деньги обычно уже давно у брокера.

## UI

### Страница `page-investments`

Sub-page без своей кнопки в навбаре (как `page-deposits`): открывается кнопкой «Инвестиции» рядом с «Вклады» на вкладке Активы; в `showPage` подсвечивает nav-кнопку Активов.

Карточка счёта:
- имя, текущая стоимость (fmtH), «вложено X · прибыль +Y ₽ (+Z%)» (прибыль зелёным/красным);
- дата последнего снимка; если снимку > 30 дней — амберная пометка «обновите стоимость»;
- кнопки: «↻ Обновить» (модалка: дата + стоимость → новый снимок), «+ Пополнить», «− Вывести».

Edit-modal (клик по карточке): имя, список снимков (дата → сумма, удаление), список пополнений/выводов (удаление), кнопка «Удалить счёт» (soft-delete + toastUndo). Правки стампуют `updatedAt`.

### Пополнение / вывод

Модалка как у вкладов (`saveDepContribution`-паттерн): дата (≤ сегодня; пополнение раньше первого снимка допустимо — в стоимости оно не участвует, т.к. снимки уже его содержат, но в «вложено» считается), сумма, опциональный селект банка:
- пополнение → «Списать из банка»: `_bankAdjust(bank, date, -amount)`;
- вывод → «Зачислить в банк»: `_bankAdjust(bank, date, +amount)`.

Так сверка периодов в аудите данных остаётся чистой.

### Вкладка Активы

- «Всего активов» = банки + живые вклады + живые инвест-счета. Строка-расшифровка: «счета X · вклады Y · инвест Z» (сегменты с нулём скрываются, как сейчас).
- В конце «Текущих счетов» — read-only строки инвест-счетов с бейджем «инвестиции» (аналог бейджа «вклад», свой цвет), клик → `page-investments`.
- `_getCurrentAssetsTotal()` НЕ трогаем — остаётся banks-only (префиллы калькулятора/целей).

### График и история — `_buildAssetSeries()`

- Добавляется `invSeries[]` (та же сетка дат): значение по `invValueAt` на каждую дату; soft-deleted счёт учитывается до его локального дня удаления (паттерн `_depDelDay`) — удаление не проваливает историю задним числом.
- Даты снимков инвестиций добавляются в общую сетку дат серии.
- Тоггл графика: «банки / +вклады и инвестиции» — вторая позиция добавляет `depSeries + invSeries`. Ключ localStorage прежний (`assetsChartDeps`).
- Таблица истории (тоггл игнорирует, показывает всё): Дата | Счета | Вклады | Инвест | Всего | Δ. Колонка «Инвест» скрывается, если инвестиций нет вообще (не ломаем текущий вид).

## Sync

- `investments` добавляется в payload (`buildPayload`) и в `mergePullData` в список record-массивов: LWW по `id` / `updatedAt`, tombstones пушатся, purge > 90 дней в `loadDB()`.
- Правка любого снимка/пополнения стампует `updatedAt` всей записи (merge на уровне счёта целиком — как у deposits с их contributions/accruals).
- `Code.gs` без изменений (generic JSON).

## Excel / Backup

- Excel: новый лист «Инвестиции» — по счёту: имя, вложено, выводы, текущая стоимость, прибыль ₽/%, дата последнего снимка.
- Резервная копия/восстановление — автоматически (полный дамп `DB`).

## Аудит данных

- Инвестиции в period reconciliation не входят (как вклады): рост стоимости — не доход в `incomes`, движения банк↔брокер идут через `_bankAdjust` и сходятся сами.
- В аудит добавить предупреждение: инвест-счёт без снимка > 60 дней.

## Не делаем (осознанно)

- Тикеры, акции, ОФЗ, автокотировки, API брокеров.
- Валюты (всё в ₽).
- XIRR / годовая доходность.
- Налоговый вычет ИИС: придёт на банковский счёт → записывается обычным доходом с тегом.
