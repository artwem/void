# V.O.I.D. — руководство для coding-агентов

## Обзор проекта

**V.O.I.D. — Visual Overview of Income & Debt** — русскоязычный личный финансовый трекер и PWA: бюджет с лимитами, ежедневные расходы, доходы, аналитика и годовой отчёт, банковские счета, вклады, инвестиции, кредиты и калькулятор накоплений. Опубликованное приложение: `https://artwem.github.io/void/`.

Основное приложение — статический клиент без локального серверного компонента и шага сборки. Данные хранятся на устройстве в `localStorage`, основные функции работают офлайн. По желанию пользователь подключает двустороннюю синхронизацию через собственный Google Apps Script; его код находится в `apps-script/Code.gs`, а JSON хранится в Google Drive.

Текущая видимая версия интерфейса — `v1.87.3`, ожидаемая версия Apps Script — `10.5`.

## Технологии и конфигурация

- Ванильный JavaScript, HTML и CSS; фреймворка, транспиляции и production-сборки нет.
- `index.html` — **единственный источник разметки и прикладного JavaScript-кода клиента**. Не создавать отдельные `js/*.js` и не добавлять сборщик: старые build-входы удалены намеренно. Service worker при этом остаётся отдельным файлом `sw.js`.
- `css/app.css` — единственный отдельный файл стилей, подключается напрямую с query `?v=`.
- `tools/package.json` и `tools/package-lock.json` относятся **только к инструментам разработки**. В корне нет `package.json`, `pyproject.toml` или другого манифеста приложения.
- Единственная прямая npm-зависимость инструментов — `puppeteer-core`; браузер не скачивается автоматически, используется установленный Chrome.
- Chart.js, SheetJS/xlsx-js-style и шрифты Golos Text и JetBrains Mono лежат локально в `vendor/`. Не возвращать CDN-загрузки: офлайн-запуск PWA не должен зависеть от CDN. XLSX-библиотека загружается лениво при экспорте Excel.
- `manifest.json` — PWA-манифест и ярлыки; `sw.js` — service worker и список предкешируемых файлов; `.nojekyll` нужен для GitHub Pages.
- CI-конфигурации `.github/workflows` в репозитории нет.

## Запуск и проверка синтаксиса

Сборка не нужна. Из корня репозитория:

```bash
python3 -m http.server 8080
# http://localhost:8080
```

Не открывать приложение только через `file://`: service worker, загрузка локальных ресурсов и синхронизация рассчитаны на HTTP(S).

Быстрый синтаксический разбор всех инлайновых скриптов:

```bash
node -e "const html=require('fs').readFileSync('index.html','utf8');const re=/<script(?![^>]*src)[^>]*>([\s\S]*?)<\/script>/g;let m,ok=true;while((m=re.exec(html))){try{new Function(m[1])}catch(e){ok=false;console.log('FAIL:',e.message)}};console.log(ok?'syntax OK':'ERRORS')"
```

Линтера, форматтера и отдельной команды production-сборки нет.

## Структура и модули

```text
index.html                 HTML, модалки и весь прикладной JS клиента
css/app.css                стили, темы и адаптивная раскладка
sw.js                      офлайн-кеш и обновление PWA
manifest.json              установка PWA и deep-link ярлыки
apps-script/Code.gs        опциональный backend синхронизации на Google Drive
vendor/                    локальные Chart.js, XLSX и WOFF2-шрифты
tools/                     Puppeteer-проверки, скриншоты и нарезка шрифтов
docs/superpowers/          исторические спецификации и планы функций
.claude/skills/            подробные инварианты прогноза и накоплений
apple-touch-icon.png       растровая иконка; исходник знака — inline SVG в index.html
```

Внутри основного `<script>` в `index.html` секции обозначены маркерами `// ═══ … ═══`. Порядок секций важен: это один глобальный JS-контекст, без ES-модулей и инкапсуляции модулей.

| Маркер | Ответственность |
|---|---|
| `db.js` | глобальный `DB`, загрузка/сохранение, миграции, форматирование, общие UI-хелперы |
| `nav.js` | страницы, навигация по датам и месяцам, виджет синхронизации |
| `budget.js` | категории, лимиты, прогресс, дневной конверт и ручная бронь |
| `day.js` | расходы дня, быстрое добавление, шаблоны |
| `interactions.js` | flash/vibe, swipe и связанные взаимодействия |
| `income.js` | доходы, источники, теги и месячный баланс |
| `stats.js` | Chart.js, аналитика, поиск расходов, прогноз и годовой отчёт |
| `assets.js` | банки, вклады, инвестиции, кредиты, история и графики активов |
| `settings.js` | настройки, CRUD списков, резервные копии, Excel, уведомления, аудит, демо-данные |
| `sync.js` | Apps Script API, merge, Drive-копии и журнал слияний |
| `calc.js` | калькулятор сложного процента и эффективной ставки |
| `init.js` | запуск, deep links, автосинхронизация и безопасная перезагрузка после обновления SW |

Стартовая вкладка — «День». Подстраницы `deposits`, `investments`, `report` и `calc` открываются через общий `showPage()`; у них нет отдельной кнопки в мобильной навигации. У годового отчёта есть отдельная кнопка в десктопном сайдбаре. После изменения данных соответствующая вкладка обычно полностью перерисовывается функцией `render*()`.

## Модель данных и важные инварианты

### Хранение

Рабочий набор находится в глобальном объекте `DB` и сериализуется в `localStorage` под ключом `budgetDB_v2`. Основные коллекции: `expenses`, `incomes`, `assets`, `templates`, `deposits`, `investments`, `credits`; справочники и настройки: `categories`, `catIds`, `catColors`, `catOblig`, `banks`, `creditBanks`, `limits`, `specPlan`, `incomeTags`, `incomeTagColors`, `incomeTagOrder`, `listsMeta`.

- `saveDB()` сохраняет данные, ставит `_dirty` и увеличивает `_dirtyGen`, чтобы синхронизация отправила изменения и не потеряла правки, сделанные во время ожидания сети.
- `saveLocal()` сохраняет без `_dirty`; использовать для настроек устройства, которые не входят в payload: темы, приватности, уведомлений.
- Большинство UI-состояний чипов и периодов хранится отдельно через `uiGet()`/`uiSet()` в `localStorage` и не синхронизируется. Не переносить эти ключи в `DB` или payload. Существующие исключения не унифицировать без отдельной причины: `limitAvgMonths` остаётся в `sessionStorage`, часть настроек графика активов читается из `localStorage` напрямую, а `syncUrl`, `syncToken` и `lastSync` используют несколько хранилищ для совместимости с iOS PWA.
- При загрузке выполняются миграции; обычные tombstones старше 90 дней удаляются, но закрытые вклады с `closedAt` являются архивом и не очищаются.

### Категории и деньги

- `DB.catIds[i]` — постоянный идентификатор категории. У расхода и шаблона `catId` авторитетен, а `cat` — производный позиционный индекс для рендера.
- При создании или редактировании расхода/шаблона обязательно сохранять `catId`. Не перезаписывать `catId` «сирот» в `_reindexCats()`: после прихода правильного списка категорий запись должна вернуться на место.
- `limits`, `catColors`, `catOblig` и `specPlan` ключуются по `catId`, не по позиции. Читать лимиты и цвета через `getLimits()` и `getCatColor()`; `_migrateCatKeyed()` поддерживает старый формат.
- Пользовательские суммы хранятся с точностью до копеек. Использовать `parseMoney()` и `formatMoneyInput()`, не округлять введённые суммы через `Math.round()` до рубля.
- Для вывода использовать `fmt()`/`fmtH()`/`fmtN()`; `fmtH()` дополнительно обеспечивает размытие в приватном режиме. `fmtDate()` — общий UI-формат дат, ISO остаётся в данных, input и экспорте.

### Прогнозы и активы

- `_monthForecast()` — единственный движок прогноза конца месяца для «Бюджета» и графика «День за днём». Печатаемый полный итог и отфильтрованная линия графика — разные вещи; не связывать их заново.
- Обязательность — свойство категории, разовость — свойство траты. Для классификации использовать `_isOblig()`, `_isOneoff()`, `_isSpec()`, а не читать `oneoff`/legacy `special` напрямую.
- `_buildAssetSeries()` — единственный источник ряда для графика, истории и аудита активов. Не добавлять производные даты в сетку реальных снимков.
- Переводы между банком и вкладом выполнять через `_bankAdjust()`. Инвестиционные переводы имеют отдельную отложенную семантику `_bankPending`; не заменять её без изучения существующих проверок.
- Перед правкой этих областей прочитать `.claude/skills/void-forecast/SKILL.md` и/или `.claude/skills/void-assets/SKILL.md`: там формулы, краевые случаи и причины отклонённых альтернатив.

### Синхронизация

Клиент обращается к развёрнутому `apps-script/Code.gs`; на Drive основной файл называется `nto_data.json`. Все обычные входы синхронизации идут через один `syncCycle()` с общим in-flight promise и порядком **pull → merge → push**. Не делать обычный push до pull. Исключение — восстановление Drive-копии, которое намеренно делает force-push после применения снимка.

- Для записей с `id` действует last-write-wins по `updatedAt`. Любое создание, редактирование, массовое переименование или переназначение записи должно обновлять `updatedAt`, иначе merge может откатить изменение.
- Удаления синхронизируемых записей мягкие: `_deleted: true`, обнуление суммы и новый `updatedAt`. Все вычисления, списки и экспорт должны исключать такие записи.
- При изменении списков вызывать `touchList(name)` для LWW по `listsMeta`. `limits` и `specPlan` имеют собственные 3-way baselines `_lastSyncedLimits` и `_lastSyncedSpecPlan`; сравнение объектов — через `_canonJSON()`.
- `buildPayload()` исключает `syncUrl`, `syncToken`, настройки уведомлений, тему, приватность, локальные baselines и `_dirty`. JSON-резервная копия использует тот же payload.
- `Code.gs` сериализует запись под `LockService`, защищается от подозрительно маленького push, поддерживает SHA-256 short-circuit и хранит семь суточных копий `nto_data.bak.YYYY-MM-DD.json`. Эти защиты не ослаблять.

## Стиль кода и UI

- Сохранять существующий стиль: глобальные функции и переменные, компактные функции, `innerHTML`, inline-обработчики в статическом HTML, общие хелперы вместо нового архитектурного слоя.
- Пользовательские строки при вставке в HTML экранировать через `esc()`. Для подтверждений использовать асинхронный `confirmDialog()`, не `window.confirm`.
- Цвета JS для тем и графиков брать из CSS-переменных через `_chartColors()`; новые жёстко заданные цвета не вводить. Цвета тем — шестизначный hex. Порядок `CAT_COLORS` не менять без повторной проверки палитры.
- Сегменты делать кнопками `type="button"` с `aria-pressed`; общее состояние обновлять через существующие хелперы. Сохранять `prefers-reduced-motion`, pinch-zoom и мобильные safe-area.
- Мобильная раскладка базовая, тело ограничено 430 px. С 1000 px включается сайдбар 64 px, с 1200 px — 208 px; с 1440 px инспектор может стать отдельной колонкой. Основные десктопные правила находятся в конце `css/app.css`.
- Комментарии и интерфейс преимущественно русские. Не переводить существующие идентификаторы и не переименовывать секции без необходимости.

## Тестирование

Установка инструментов:

```bash
cd tools
npm ci
```

Полный прогон из корня:

```bash
node tools/dt-check.mjs
```

Либо из `tools/`: `npm run check`. Раннеру нужен системный Chrome. По умолчанию в `tools/harness.mjs` задан Windows-путь; на другой системе передать `CHROME_PATH`. Проверенная команда для macOS:

```bash
CHROME_PATH='/Applications/Google Chrome.app/Contents/MacOS/Google Chrome' node tools/dt-check.mjs
```

Харнесс сам поднимает временный статический HTTP-сервер и запускает Chrome, поэтому отдельный `python3 -m http.server` для тестов не нужен. Service worker в тестовых страницах отключён.

`tools/dt-check.mjs` — не только геометрия: там поведение DOM, миграции, форматирование, прогнозы, вклады, инвестиции, синхронизация, резервные копии и Excel. Каждая сюита получает свежую страницу; проверки внутри одной сюиты выполняются последовательно и могут зависеть от порядка. Новые проверки добавлять через `suite(width, title, fn, opts)` и `check(name, fn)` рядом с соответствующей областью.

Два набора данных:

- `FIXTURE` из `tools/harness.mjs` — небольшой арифметически прозрачный набор. Его старый позиционный формат лимитов специально проверяет миграцию; не менять суммы без пересмотра ожиданий существующих проверок.
- `suite(..., {demo:true})` использует `buildDemoDB(now)` из секции `settings.js`. Это тот же генератор, что доступен пользователю через пять тапов по иконке в «О программе». Не создавать второй демо-генератор в тестах. Раннер выполняет fixture- и demo-сюиты двумя отдельными проходами.

Скриншоты:

```bash
node tools/shots.mjs
# при необходимости задать CHROME_PATH так же
```

Снимаются десять страниц на ширинах 390, 1000, 1280, 1440 и 1600 px, затем модалки на 390, 1280 и 1600 px. Используется демо-набор. Результат попадает в игнорируемый `tools/shots/`; после визуальной проверки не коммитить его. После изменений вёрстки или графиков обязателен полный `dt-check`, а ручная проверка Safari/iOS, Chrome/Android и десктопа остаётся дополнительной: Puppeteer их не заменяет.

`tools/subset-fonts.sh` — разовая утилита для обновления шрифтов через `uv`, `fonttools` и `brotli`; её не нужно запускать при обычных правках.

## Деплой

### GitHub Pages

Публикация идёт из ветки `main` в `artwem/void`, отдельного workflow или шага сборки нет.

Перед каждым деплоем:

1. Обновить видимую версию в блоке «О программе» в `index.html`.
2. Обновить `const V` в `sw.js`: новое значение создаёт новый кеш и заставляет iOS PWA обновиться.
3. При любом изменении `css/app.css` обновить query `?v=` в `<link rel="stylesheet">` в `index.html`.
4. Если добавлен runtime-ресурс, который нужен офлайн, добавить его в `PRECACHE` в `sw.js` и загрузить в приложении.
5. Прогнать синтаксическую проверку и браузерные тесты, затем опубликовать изменения в `main`.

Service worker использует network-first для навигационного HTML и cache-first для остальных same-origin GET-ресурсов; ошибочные ответы не кешируются. Перезагрузка после обновления откладывается, если открыта модалка или пользователь вводит данные, — не возвращать безусловный reload.

### Apps Script

Изменение `apps-script/Code.gs` не публикуется вместе с Pages автоматически. Код нужно вручную скопировать в редактор Apps Script и создать новую версию развёртывания веб-приложения («Выполнять как: Я», доступ «Все»). При изменении протокола синхронно обновлять `VERSION` в `Code.gs` и ожидаемую `APPS_SCRIPT_VERSION` в `index.html`, а также проверять совместимость старых клиентов.

## Безопасность и данные пользователя

- В репозитории и тестах не использовать реальные финансовые данные. `backup.json`, `budget_backup_*.json`, `tools/shots/` и `tools/node_modules/` игнорируются git.
- Если `SECRET` в `Code.gs` пуст, аутентификации нет: URL публичного веб-приложения фактически является доступом к данным. Для защиты задать общий `SECRET` и тот же токен в настройках приложения.
- `syncToken` хранится на устройстве в local/session storage и cookie и не входит в Drive-payload или JSON-бэкап. Не добавлять его в экспорт, логи, скриншоты или тестовые фикстуры.
- Все пользовательские строки в `innerHTML` экранировать. Денежные значения в HTML выводить через приватность-aware хелперы; в уведомлениях учитывать, что CSS-размытие на системном экране не работает.
- `readBackup` должен продолжать ограничиваться файлами `nto_data.bak*`, чтобы переданный ID не превращал Apps Script в чтение произвольных файлов Drive.
